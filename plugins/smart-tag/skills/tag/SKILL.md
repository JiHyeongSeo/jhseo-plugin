# Smart Tag - 대화형 배포 태그 생성

Git 태그 생성부터 Confluence 패치 노트 작성까지 대화형으로 진행하는 스킬입니다.

## 트리거 키워드

다음 키워드가 포함된 요청에서 활성화됩니다:
- "태그", "tag", "배포", "deploy", "릴리즈", "release"
- "패치노트", "patch note", "배포 노트"

## 워크플로우

```
1. 사용자: "/tag" 명령 입력
   ↓
2. Claude: 최근 커밋 목록 표시 (최근 10개)
   ↓
3. Claude: 대화형 질문
   - 어느 커밋에 태그를 달까요?
   - 환경은? (dev/stage/prod)
   - 버전은? (예: 1.2.3)
   ↓
4. Claude: git tag 생성
   - 형식: {환경}-v{버전}
   - 예: dev-v1.2.3
   ↓
5. Claude: 패치노트 커밋 범위 확인 (중요!)
   - 이전 태그 자동 탐색 결과 표시
   - "패치노트에 포함할 커밋 범위를 확인해주세요"
   - 기본값: {이전태그}..{현재태그}
   - 사용자가 다른 범위를 지정할 수 있음
   ↓
6. Claude: 태그 푸시 여부 질문 (중요!)
   - "태그를 원격 저장소에 푸시하시겠습니까?"
   - 옵션: 예 / 아니오
   - 예 선택 시: git push origin {태그명}
   ↓
7. Claude: deployment.py 자동 실행
   - 패치노트 생성
   - 릴리즈 노트 생성
   ↓
8. Claude: 결과 출력
   - Confluence URL
   - 태그 푸시 여부
```

## 환경 설정

**필수 환경변수:**
```bash
export CONFLUENCE_API_TOKEN="your-bearer-token"
```

## 지원 레포지토리

현재 다음 레포지토리를 지원합니다:
- **engagement_api_fastapi** (텍스트/이미지탐지 API)
  - 태그 형식: `{환경}-v{버전}`
  - 환경: `dev`, `stage`, `prod`

## 태그 형식

```
{환경}-v{버전}
```

예시:
- `dev-v1.0.0` - 개발 환경
- `stage-v1.2.3` - 스테이징 환경
- `prod-v2.0.0` - 운영 환경

## 자동 생성 문서

태그 생성 시 **두 가지 문서**가 자동으로 Confluence에 생성됩니다:

### 1. 간략한 패치노트
- **위치**: "텍스트/이미지 탐지 API 패치노트" 하위
- **제목 형식**: `(YYYY/MM/DD) v{버전} {커밋 요약}`
- **내용**:
  - 배포 이력 테이블 (환경별 배포 일시)
  - 주요 변경 사항 (최대 5개 커밋)
  - 상세 릴리즈 노트 링크

### 2. 상세 릴리즈 노트
- **위치**: "상세 릴리즈 노트" 페이지 하위
- **제목 형식**: `v{버전} 릴리즈 노트`
- **내용**:
  - 배포 이력 테이블
  - 전체 커밋 히스토리
  - 변경된 파일 목록
  - 배포 절차 및 체크리스트
  - 롤백 계획

## 버전별 단일 문서 관리

같은 버전은 환경에 관계없이 **하나의 문서**로 관리:
- 첫 배포 (dev-v1.2.3): 새 문서 생성
- 두 번째 배포 (stage-v1.2.3): 배포 이력에 stage 추가
- 세 번째 배포 (prod-v1.2.3): 배포 이력에 prod 추가

최종 배포 이력:
| 환경 | 배포 일시 |
|------|-----------|
| 개발 (dev) | 2026-02-04 |
| 스테이징 (stage) | 2026-02-05 |
| 운영 (prod) | 2026-02-10 |

## 대화형 질문 예시

Claude가 물어보는 질문들:

1. **커밋 선택**
   - "최근 10개 커밋입니다. 어느 커밋에 태그를 달까요?"
   - 옵션: 커밋 해시 또는 "맨 위", "2번째" 등

2. **환경 선택**
   - "배포 환경을 선택하세요"
   - 옵션: dev / stage / prod

3. **버전 입력**
   - "버전을 입력하세요 (예: 1.2.3)"
   - Semantic Versioning 형식

4. **최종 확인**
   - "{환경}-v{버전} 태그를 생성하고 패치노트를 작성하시겠어요?"
   - 옵션: 예 / 아니오

5. **패치노트 커밋 범위 확인** (중요!)
   - "패치노트에 포함할 커밋 범위를 확인해주세요"
   - 이전 태그 자동 탐색: {이전태그} 표시
   - 기본 범위: `{이전태그}..{현재태그}` (예: dev-v1.2.2..dev-v1.2.3)
   - 옵션:
     - 기본 범위 사용 (추천)
     - 다른 시작점 지정 (예: 특정 커밋 해시 또는 다른 태그)
     - 전체 히스토리 (이전 태그 없을 시)

6. **태그 푸시 여부** (중요!)
   - "태그를 원격 저장소에 푸시하시겠습니까?"
   - 옵션: 예 / 아니오
   - 푸시하면 CI/CD 파이프라인이 트리거될 수 있으므로 반드시 사용자에게 확인

## 자동 수집 정보

배포 노트에 자동으로 포함되는 정보:
1. **Git Commit 히스토리**: 이전 태그부터 현재 태그까지
2. **변경된 파일 목록**: 추가/수정/삭제된 파일 및 변경 라인 수
3. **배포 환경 및 버전**: 태그에서 파싱
4. **배포 일시**: 태그 생성 시간

## 내부 동작

### 1. 커밋 조회
```bash
git log --oneline -10
```

### 2. 태그 생성
```bash
git tag {환경}-v{버전} {커밋-해시}
```

### 3. 이전 태그 탐색 및 커밋 범위 확인
```bash
# 같은 환경의 이전 태그 찾기
git tag --sort=-version:refname | grep "^{환경}-v"

# 커밋 범위 미리보기
git log --oneline {이전태그}..{현재태그}

# 커밋 수 확인
git rev-list --count {이전태그}..{현재태그}
```

### 4. 태그 푸시 (사용자 확인 후)
```bash
# 사용자가 "예"를 선택한 경우에만 실행
git push origin {환경}-v{버전}
```

### 5. 패치노트 생성
```bash
# --prev-tag 옵션으로 커밋 범위 지정 가능
python ${PLUGIN_DIR}/deployment.py create --tag {환경}-v{버전} --prev-tag {이전태그} --no-interactive
```
